# Code signing policy

Git commits are deliberately unsigned; tags do not require cryptographic signatures. Commits retain DCO `Signed-off-by` trailers; stable `vMAJOR.MINOR.PATCH` tags must be annotated and created by Thomas Lothian through the repository workflow. The [unsigned-history migration](docs/history/UNSIGNED_COMMITS.md) records earlier removal of signed commits.

Thomas Lothian is the sole maintainer and final release approver. An official stable EWAF release is a GitHub Release from an owner-created annotated tag, with platform artifacts built and tested from that exact commit. A tag alone does not make an unverified artifact official. Prereleases and development builds are clearly marked.

Stable macOS artifacts require Developer ID signing, Apple notarization and staple verification. Stable Windows artifacts require Azure Artifact Signing and Authenticode verification. Linux updates are authenticated by the installed EWAF-specific Ed25519 public key, the signed release manifest and the exact AppImage digest and size. GitHub/Sigstore build attestations provide additional provenance; the AppImage itself has no separate signing-key requirement. Production credentials remain in Keychain or protected CI secrets, never the repository or build artifacts. CI must fail closed when a required Apple, Windows or update-manifest credential or validation step is unavailable. Each platform publishes only after its required checks succeed.
