# Licensing and Windows distribution audit

Assessed 2026-09-24. **Decision:** original EWAF code and build scripts are GPL-3.0-or-later, as expressed by the root [GPL text](../LICENSE) and Cargo SPDX metadata. Microsoft code receives no GPL grant from this repository. The current self-contained Windows ZIP needs a separate distribution review before a new release. This is an engineering and license-text assessment, not a legal opinion or a SignPath eligibility decision.

## Governing rules

[GPLv3 §1](https://www.gnu.org/licenses/gpl-3.0.en.html) defines System Libraries by normal packaging of a major OS/compiler/interpreter component and a functional test, then excludes them from Corresponding Source. [GNU's Windows runtime FAQ](https://www.gnu.org/licenses/gpl-faq.en.html#WindowsRuntimeAndGPL) treats installed Microsoft VC++ runtime DLLs as System Libraries but says DLLs distributed with the GPL program lose that exception. [GNU's GPLv3 guide](https://www.gnu.org/licenses/quick-guide-gplv3.html) says common language runtimes can qualify even when separately installed. These sources do not automatically classify WinUI 3.

The exact [Windows App SDK 2.4.0 NuGet binary terms](https://www.nuget.org/packages/Microsoft.WindowsAppSDK/2.4.0/License) allow redistribution of files binplaced with the app in both deployment modes (§3(a)(i)), while imposing distributor/end-user and indemnity requirements (§3(b)) and restricting source-disclosure terms on Microsoft code (§3(c)(ii)). **Redistributable** does not mean **GPL licensed**. The [Windows App SDK source repository MIT license](https://github.com/microsoft/WindowsAppSDK/blob/main/LICENSE) is distinct from the NuGet binary terms.

The official [Windows SDK REDIST.TXT list](https://learn.microsoft.com/en-us/legal/windows-sdk/redist) expressly permits the unmodified `Microsoft.Windows.SDK.NET.Ref` package files, including `lib/net8.0/Microsoft.Windows.SDK.NET.dll` and `WinRT.Runtime.dll`, to be distributed as part of an application that calls WinRT APIs. EWAF does call WinRT/WinUI APIs. This establishes **redistribution permission** for those exact SDK projection files under the Windows SDK terms; it does not relicense the binary as GPL or settle SignPath classification. An older [Microsoft Q&A response](https://learn.microsoft.com/en-us/answers/questions/1696668/can-i-redistribute-microsoft-windows-sdk-net-dll) said otherwise, but the explicit official REDIST list is more authoritative and controls this audit.

[SignPath Foundation's OSS conditions](https://signpath.org/terms.html) require OSI-approved licensing for components and bar proprietary code, but **expressly allow System Libraries in signed packages**. They also say to sign only one's own binaries and allow unsigned upstream OSS binaries inside signed packages. Whether particular Microsoft App SDK files qualify for its exception is for SignPath to decide. GPL compatibility, redistribution permission and SignPath eligibility are separate conclusions.

## Four separate conclusions and smallest practical path

1. **Own source:** GPL-3.0-or-later applies now to EWAF-owned code. This grants no rights in Microsoft's code.
2. **Redistribution:** Windows App SDK 2.4.0 explicitly permits binplaced files subject to its terms. Microsoft's official SDK REDIST list separately permits the unmodified .NET projection DLLs in this WinRT-using app. Notices must still accompany the relevant components.
3. **Combined Windows ZIP:** Current app-local proprietary WinUI/ML files are not demonstrated GPLv3 System Libraries. Their presence raises a concrete combined-distribution question, **not automatic GPL incompatibility**. Microsoft distribution conditions must be reconciled with GPL obligations where the works are genuinely combined.
4. **SignPath:** Its explicit System Libraries exception could cover installed OS/runtime components, but cannot be presumed for every separately supplied App SDK DLL. SignPath eligibility is distinct from GPL compatibility; only SignPath can accept the actual package. Azure Artifact Signing is currently the documented Windows signing target.

**Smallest practical change if needed:** keep WinUI 3 and GPL code. Build a framework-dependent Windows variant by removing `WindowsAppSDKSelfContained=true` and using `dotnet publish --self-contained false`; require separately installed Windows App SDK runtime, .NET 8 runtime and VC++ Redistributable. Do not put Microsoft's runtime installer/MSIX/DLLs in EWAF's ZIP. [Microsoft's unpackaged deployment guide](https://learn.microsoft.com/en-us/windows/apps/windows-app-sdk/deploy-unpackaged-apps) documents the runtime and bootstrapper prerequisites. This changes copy-only use to a one-time prerequisite, so test clean Windows 10/11 x64 and ARM64 startup, install/uninstall and updates before adopting it. Audit the remaining app-local bootstrapper and SDK projection DLLs for combined-package and SignPath treatment. Recommend another source license only if a concrete unavoidable incompatibility survives these options.
