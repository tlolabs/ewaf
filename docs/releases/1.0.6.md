# EWAF 1.0.6

This patch continues the October 30 bug-fix work. The application version is 1.0.6 in Cargo, CMake, Cargo.lock, and the generated native Xcode project. No release tag or publication is part of this change.

## Changes

- Shared Qt previews export plain text during dragging, copy the first row when nothing is selected, select the context-menu row, and synchronize menu availability with workspace state.
- Searching preserves a valid creation plan. Calendar pickers cover years 1–9999 and retain whitespace-wrapped exact dates through Rust validation.
- JSON preferences preserve numeric and boolean values. Tests distinguish the Windows registry from the Linux/internal-reference JSON backend and isolate test preferences.
- Windows installer dialogs use UTF-16 conversion. Existing handle-wrapper additions are retained as hardening; a concrete original sentinel-handling failure was not demonstrated.
- Version diagnostics now reject stale Cargo.lock and Xcode version copies, including when Python optimization is enabled.

Production macOS retains SwiftUI/AppKit and existing preference keys and Codable dates. Windows and Linux retain the shared Qt presentation. Date, folder-naming, filtering, confirmation, conflict, and recovery rules remain in Rust. Update authentication and independent platform publication policy are preserved.

## Verification

The [follow-up report](../audits/2026-10-30-follow-up-and-version-1.0.6.md) records the exact source snapshot, commands, observed results, independent focused reviews, and limitations. Windows and Linux native acceptance requires their own runners. Shared Qt results on macOS do not establish those results. Direct downloads and authenticated automatic updating retain their separate trust requirements.
