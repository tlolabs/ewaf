### Windows handoff contract and remaining acceptance

READY means the selected MSI has passed digest, Authenticode publisher and MSI identity/architecture verification while the file and ordinary ancestors remain held. COMMITTED means the helper has accepted consented normal-exit handoff; it **does not mean MSI succeeded**. The helper waits for the original PID/start-time identity, checks other EWAF processes, never kills them, and treats timeout/enumeration failure as cancellation. MSI failure/3010 recovery remains explicit. The wrong portable relaunch is removed in favor of the established installed-shortcut workflow.

The Qt reaper has no application parent: before commitment an abort sends ABORT and, while the loop runs, kills only an unresponsive installer helper after two seconds. After commitment it never terminates that child. While EWAF stays open, finished deletes the QProcess and closes its resources; at parent process exit the OS reclaims parent-side memory/handles without invoking a destructor that kills the committed child. Actual Windows job/process semantics still require the added native test. If active work begins before handoff checks, installation aborts/refuses closure; post-COMMIT timeout/failure behavior and independently launched windows must be exercised on Windows.

`tests/windows/installer_parent_exit.ps1` is invoked by the existing native updater test script only on a disposable GitHub-hosted runner. It uses the real signed fixture MSI and native helper, receives READY/COMMITTED, permits the supervisor to retain the installer OS handle, then exits its real parent normally. The supervisor asserts installer exit 0, installed executable hash, and preservation of a uniquely controlled generated-folder fixture. Unicode paths/publisher, parent junction rejection, locked MSI, invalid identity/signature and ABORT are covered. These are **new unexecuted Windows acceptance fixtures**, not passed tests. No workflow was triggered.

### Linux policy and recovery analysis

Private home directories and normal root-owned ancestors are allowed. Group/world-writable ancestors require sticky semantics and trusted ownership; `/tmp` is suitable only above a privately writable, app-owner directory. A directly shared immediate parent still fails closed because lock/journal ownership depends on it. Private user-controlled mount paths follow the same rules; another user's mount root is not trusted merely because readable. Parent symlink aliases are rejected. Root-owned group-writable nonsticky mount directories are unsafe too.

Linux resolves mutable transaction paths through its held directory descriptor. Renames cannot redirect those child operations. Identity/owner/permission/canonical-parent checks run again before journal and image persistence. Stable lock inode, image identity, authenticated staged bytes/ELF architecture, durable monotonic version floor and retained executable backup remain in force. Exact interrupted-version/digest retry is preserved. Tests cover concurrent instances, interrupted staging, corrupt bytes, locked original, changed image, unsafe journal, rollback floor, symlinks, unsafe modes and the final ancestor-swap point.

Actual `/proc/self/fd` behavior, permissions/ACLs, real sticky mounts, read-only media, low storage, power-loss sync/rename behavior and interruption of a running Linux helper remain native acceptance work. An unavailable procfs fails closed. The security boundary does not promise resistance to root or malicious same-user control of the running process; permissions changed by that actor after the final check are not transformed into an authentication guarantee.
